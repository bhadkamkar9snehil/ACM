Chapter 1

1What Is ACM?

ACM (Asset Condition Monitor) watches industrial assets — pumps, compressors, wind turbines, pipeline sections — and tells you when something is wrong. The core constraint: no labels, ever. You can't tell ACM "this event was a fault". It has to figure that out entirely from the raw sensor history.

The problem: Industrial equipment fails slowly, irregularly, and differently every time. Labels are scarce (you only label faults you already found), anomaly rates are low (<1%), and each site has different sensors, cadences, and operating envelopes. Per-site threshold tuning is expensive and brittle.

ACM's answer

Fully unsupervised. On every tick:

  1. Read the new sensor rows from the historian (CSV, SQL, OPC UA, or MQTT).
  2. Re-learn "normal" from scratch on the trailing history (no persisted model files).
  3. Score the recent window against that learned normal using six independent detectors.
  4. Fuse the detector scores with correlation discounting.
  5. Run cadence-aware alarm rules that tune their own thresholds from the same history.

What ACM is not

  • Not a supervised model. No training set, no ground-truth labels, no per-asset retraining campaign.
  • Not a rule engine. No engineer sets "temperature > 85°C = alert".
  • Not stateful across ticks. Every tick re-fits detectors on the full trailing window. The "memory" is the parquet cache, not a persisted model object.

2The Pipeline

Every call to score_asset() in core/pipeline.py executes these stages in order, with no mutable state carried across calls.

Stage overview

StageWhat happensKey output
1. Channel rolesClassify each sensor as PRIMARY (raw) or DERIVED (pre-computed window stat like _min/_max/_std). Derived channels skip rolling feature engineering to avoid compounding noise.primary / derived lists
2. Rolling featuresCompute per-sensor rolling statistics over a 16-sample window: median, MAD, mean, std, OLS slope, skew, kurtosis, spectral energy (3 FFT bands). All in Polars, float32.Feature matrix
3. Interleaved splitEvery 5th block of rows becomes the calibration holdout (≈20%). The remaining ≈80% are the training set. NOT a tail holdout — blocks are interleaved across the full history to prevent seasonal bias.train / score DataFrames
4. Six detectorsFit each detector on training rows, score all rows. Each detector produces a raw anomaly score per timestamp.Raw score arrays
5. CalibrationConvert each raw score to a robust Z-score using the holdout's median/MAD (with contamination filtering). Each detector gets its own calibrator.Z-score arrays
6. FusionWeighted sum of Z-scores, with correlation discounting (detectors that fire together have their combined weight reduced). Auto-tuned weights converge toward detectors that best separate episodes.Fused Z-score
7. Alarm rulesFour cadence-aware rules (sustained, rate, per-head, availability) plus a self-distrust gate. All thresholds derived from the same history.ALERT mask + rule fired

The interleaved split (critical detail)

Most anomaly detectors use a tail holdout: "first N% is training, last M% is scoring." ACM uses an interleaved holdout: every 5th block across the whole history is the calibration set. This means:

  • Calibration captures variance from across all seasons, load regimes, and day/night patterns.
  • A tail holdout on a 2-week window would calibrate only against last week's operating conditions. An interleaved holdout captures the full distribution.
  • The training set is the remaining ~80% (non-holdout blocks).
Interleaved split — visualised (stride = 5)

Orange = calibration holdout (every 5th block). Blue = training. The detector is fit on blue, calibrated on orange.

Stateless re-fit

The pipeline carries no model state between ticks. On every tick: read parquet → split → fit → score → calibrate → fuse → alarm. This means the model always reflects the latest "normal" baseline. A long holiday shutdown doesn't poison the model — it simply becomes part of the new normal on return.

Adaptive score window

To prevent young assets from starving their training set, ACM uses an adaptive score window:

score_eff = min(score_days, max(1.0, span_days / 3.0))

This ensures the scoring window is never more than a third of the available history, keeping the train/score ratio sensible even during the maturation phase.

Chapter 3

3Feature Engineering

Raw sensor values are poor inputs for detectors because they conflate level changes with variance changes, and are sensitive to scale. ACM computes rolling statistics that make deviations from "normal" directly comparable across sensors.

Window size: 16 samples

All rolling statistics use a 16-sample window. At 10-minute SCADA cadence this is ~2.7 hours. At 1 Hz this is 16 seconds. The window is intentionally short to be responsive to rapid changes; the detectors themselves operate on the full history.

Feature families

FeatureFormula (per sensor)Catches
_medRolling median (16-sample)Level shift robustly (ignores outliers)
_madRolling MAD (16-sample)Variance change robustly
_meanRolling mean (16-sample)Level shift including outlier influence
_stdRolling std (16-sample)Variance change (outlier-sensitive)
_slopeRolling OLS slope (16-sample)Trends and ramps
_skewRolling skewness (clipped ±100)Distribution asymmetry shift
_kurtRolling kurtosis (clipped ±1000)Impulsive / heavy-tailed behaviour

_energy_0/1/2log1p(Σ|FFT|² in band), 3 bands: [0, 0.1], [0.1, 0.3], [0.3, 0.5] × NyquistSpectral regime changes (bearing freq, harmonics)

Channel role detection

If a historian exports both raw values and pre-computed window stats (e.g., PUMP_SPEED, PUMP_SPEED_min, PUMP_SPEED_max, PUMP_SPEED_std), computing rolling statistics on top of the pre-computed stats adds noise without signal. ACM's detect_channel_roles() identifies derived channels by verifying the mathematical relationship on the actual data:

  • _min candidates: x_min ≤ base for ≥98% of samples
  • _max candidates: x_max ≥ base for ≥98% of samples
  • _std candidates: x_std ≥ 0 for ≥99% of samples AND median(x_std) ≤ 3× spread(base)

Anything that doesn't verify is treated as PRIMARY. The safe default is always to engineer more features.

Interactive: rolling features on a sensor signal

The robust Z-score

The _rz feature normalises each sensor onto the same scale without being pulled by outliers:

rz = (x[t] - rolling_median[t]) / (1.4826 × rolling_MAD[t])

The 1.4826 factor makes MAD numerically consistent with standard deviation for Gaussian data (MAD ≈ 0.6745σ → 1/0.6745 ≈ 1.4826). For non-Gaussian data this preserves rank-ordering without distorting the scale.

Spectral energy (FFT bands)

Each sensor's 16-sample window is FFT'd and energy is summed in three normalised-frequency bands:

BandNormalised freq rangeAt 1 Hz sampling (Nyquist = 0.5 Hz)
Band 0 (low)0 – 0.1 × Nyquist0 – 0.05 Hz (very slow oscillations)
Band 1 (mid)0.1 – 0.3 × Nyquist0.05 – 0.15 Hz (medium periodicity)
Band 2 (high)0.3 – 0.5 × Nyquist0.15 – 0.5 Hz (rapid oscillations / noise)

Energy values are log1p-compressed to prevent the quadratic scaling of raw FFT power from dominating downstream detectors.

4The Six Detectors

ACM runs six independent detectors in parallel. Each catches a different class of anomaly. The diversity is intentional: no single detector is good at everything, and their disagreements are as informative as their agreements.

AR1 w=0.20
Auto-regressive residuals. Catches slow drift and mean-shift that a model of "today predicts tomorrow" misses.
PCA-SPE w=0.30
Reconstruction error. Catches structural novelty — a combination of sensors that has never appeared before.
PCA-T² w=0.20
Hotelling's T². Catches regime shift in the principal component space — operating in a known but unusual configuration.
IForest w=0.15
Isolation Forest. Catches transient spikes and outlier clusters — points that are "easy to isolate" from the rest.
GMM w=0.05
Gaussian Mixture Model. Catches mode changes — operation at low likelihood under the learned normal envelope.
OMR w=0.10
Per-feature OMR residuals. Catches per-sensor anomalies; used to rank which channel is misbehaving.
The weights shown above (AR1=0.20, PCA-SPE=0.30, PCA-T²=0.20, IForest=0.15, GMM=0.05, OMR=0.10) are starting points. ACM auto-tunes these per asset using episode separability metrics, blended with exponential moving average (learning rate 0.30).

AR1 — Auto-Regressive Residuals

Hyperparameters: window=256, alpha=0.05 (significance), z_cap=8.0

AR1 fits a first-order auto-regressive model: x[t] = φ·x[t-1] + ε[t]. The residuals ε[t] should be zero-mean white noise under normal conditions. When the asset drifts, transitions, or changes mean, the residuals become systematically non-zero.

Why window=256? At 10-minute cadence, 256 samples ≈ 1.8 days. This is long enough to learn stable operating dynamics but short enough to adapt to load changes over a few shifts.

AR1 residuals: normal vs drift

Blue = AR1 residuals (normal). Orange = residuals during slow drift. The residuals develop a sustained bias when the trend outpaces the AR model.

PCA-SPE and PCA-T²

Hyperparameters: n_components=5, svd_solver="randomized", batch_size=4096

PCA finds the 5 directions of maximum variance in the sensor feature matrix. Think of them as the "normal operating modes" of the asset. Every new observation is then characterised by:

  • T² (Hotelling's T²): How far is this point from the centre in the principal component space? High T² = operating at an unusual combination of the known modes.
  • SPE (Squared Prediction Error): How well does the PCA model reconstruct this point? High SPE = the observation requires a new direction not in the training data — structural novelty.
PCA score plane: T² and SPE

Each point is one timestamp projected onto the first two PCs. Blue = training (normal). Orange = anomalous points. Inner ellipse = T² control limit. A point outside the cluster but near the plane has high T²; a point off the plane has high SPE.

Why 5 components?

5 PCs typically explain 80–95% of variance in industrial sensor data, capturing the dominant operating modes (load, speed, temperature). More components add noise; fewer miss important correlations. The randomized SVD solver makes this efficient for wide feature matrices (hundreds of sensors).

Isolation Forest

Hyperparameters: n_estimators=100, max_samples=2048, contamination=0.01, random_state=17

Isolation Forest builds 100 random decision trees. For each tree, a point's anomaly score is its average path length to isolation: anomalies are few and different, so they isolate quickly (short path). Normal points cluster together and take longer to isolate (long path).

Isolation path length: normal vs anomaly

Average isolation depth across 100 trees. Short path (left) = easy to isolate = anomaly. Long path = clustered with normal data.

max_samples=2048

Each tree is built on a random subsample of 2048 training points (not the full history). This controls memory use, prevents the path-length ceiling problem on large datasets, and adds randomness that makes the ensemble robust. At 10-min cadence, 2048 samples ≈ 14 days.

Gaussian Mixture Model (GMM)

Hyperparameters: k_min=2, k_max=3, covariance_type="diag", n_init=3, BIC search

GMM fits k Gaussian components to the feature matrix. Each point's anomaly score is its negative log-likelihood under the mixture: score = -log p(x | GMM). Points that fall in low-density regions (between clusters, or far from any cluster) get high scores.

BIC search for k

ACM tries k=2 and k=3, fits GMM for each, and picks the k that minimises BIC (Bayesian Information Criterion). BIC balances fit quality against model complexity: adding a component only helps if it genuinely splits the data into distinct operating modes.

Diagonal covariance

Using diagonal covariance (no cross-sensor correlation inside each component) keeps fitting stable on high-dimensional feature matrices. Full covariance would require estimating n_features² parameters per component, leading to near-singular matrices.

GMM: two operating modes (k=2) + anomaly scoring

Blue = low load regime, teal = high load regime. Orange × = anomalous points in low-density regions. GMM score is the negative log-probability under the fitted mixture.

OMR — Per-Feature Residuals

Hyperparameters: n_components=5, model_type="auto", min_samples=100

OMR fits a dimensionality-reduction model (PCA or similar) per sensor, then scores each sensor's residual independently. Unlike PCA-SPE (which gives one score for the whole asset), OMR gives one score per sensor. This directly identifies which channel is misbehaving, powering ACM's "culprit sensor" ranking.

OMR also feeds the per-head alarm rule (R3). If one sensor's OMR score fires repeatedly over 7 days while the fused score stays normal, it can still raise an R3 alarm — catching sensor-specific faults that the fused signal dilutes.

5Calibration

Each detector produces a raw score in its own units: AR1 gives residual magnitudes, IForest gives path ratios in [0,1], GMM gives negative log-likelihoods. You can't meaningfully fuse these without first putting them on a common scale.

The ScoreCalibrator

ACM uses a MAD/median calibrator (ScoreCalibrator in core/fuse.py). For each detector:

  1. Filter contamination from the holdout scores (see below).
  2. Compute median and MAD of the cleaned holdout scores.
  3. Convert to Z-score: z = (x - median) / (1.4826 × MAD)
  4. Self-tune the threshold: set at the quantile corresponding to a 0.1% false-positive rate on the holdout.
# ScoreCalibrator.fit() core logic
x_clean = contamination_filter(x_holdout)
med = np.median(x_clean)
mad = np.median(np.abs(x_clean - med))
scale = mad * 1.4826
q_thresh = np.quantile(x_clean, 0.999)  # target_fp_rate = 0.001

Contamination filtering

Training data is rarely clean — faults happen during the historical window too. If anomalous scores contaminate the holdout, the calibrator's median and MAD become inflated, making the threshold too permissive (more false negatives). ACM filters them out first using iterative MAD:

  1. Compute median and MAD of the current data.
  2. Exclude points where |z_MAD| > 4.0 (more than 4 robust sigmas from median).
  3. Recompute median and MAD on the retained data.
  4. Repeat until the median converges (tol=0.001) or 10 iterations.
  5. Guard: never exclude more than 30% of the data.
Contamination filtering: before and after

The contaminated histogram (left) has a heavy upper tail from fault events in the training window. After filtering, the tail is removed and the calibrator sees a clean "normal" distribution.

Why MAD instead of mean/std?

StatisticBreakdown pointBehaviour with 10% outliers
Mean + Std0%One outlier can inflate σ arbitrarily
Median + MAD50%Up to 50% contamination before breakdown

With contamination rates up to 30% in real fault histories, MAD calibration prevents thresholds from being set too high to detect real faults.

Z-score clipping

Calibrated Z-scores are hard-clipped to ±8.0 (adaptive) and ±10.0 (hard limit). This prevents one catastrophically-failed sensor from dominating the fused score and saturating the display. The adaptive clip is set at 1.5× the 99th percentile of training Z-scores.

6Fusion

Six calibrated Z-scores must be combined into one fused anomaly score. A simple average would be dominated by correlated detectors. ACM uses correlation-discounted weighted fusion.

Starting weights

DetectorStarting weightRationale
PCA-SPE0.30Best overall at structural novelty; most sensitive on wide sensor sets
AR10.20Strong on slow drift; highly interpretable residuals
PCA-T²0.20Complements SPE by catching in-plane shifts rather than out-of-plane novelty
IForest0.15Good on transient spikes; uncorrelated with PCA detectors
OMR0.10Per-channel resolution; useful for culprit ranking
GMM0.05Mode-change; tends to correlate with PCA-T² so gets lower starting weight

Correlation discounting

When two detectors fire together consistently (Spearman ρ > 0.95 by default), their combined weight is reduced. The intuition: if PCA-SPE and PCA-T² both fire on the same events, you haven't gained two independent votes — you've got one signal counted twice. Discounting brings the effective contribution back to one.

# Pseudo-code for correlation discount
for det_a, det_b in all_pairs:
    rho = spearmanr(z_a, z_b).correlation
    if abs(rho) > 0.95:
        w[det_a] *= (1 - abs(rho)) / 2
        w[det_b] *= (1 - abs(rho)) / 2
weights = renormalize(weights)

Auto-tuning

On each tick, ACM optionally tunes the weights using episode separability: for each detector, it computes how well that detector distinguishes known anomaly episodes from normal periods. Detectors with higher episode separability get more weight. The update is blended with the existing weights:

w_new = (1 - lr) × w_old + lr × w_episode
# lr = 0.30 (learning rate)
# Per-detector drift is clamped to ±20% per tick

7Alarm Rules

R1 — Sustained anomaly

The fused score must stay above the alert threshold for at least persist consecutive samples, where persist is 1.5× the longest healthy excursion seen in the training set (minimum: 1h of samples).

# Self-tuning: find the lowest quantile threshold
# whose implied persistence is physically sensible
for q in (0.98, 0.99, 0.995, 0.999):
    thr = max(ALERT_Z_FLOOR, quantile(train_fused, q))
    persist = max(persist_floor, longest_run(train_fused >= thr) × SAFETY + 1)
    if persist <= max_persist:  # max 12h
        break

The 1.5× safety factor (SAFETY) means the alarm only fires when the anomaly lasts longer than the worst-case healthy excursion would ever last by chance. This eliminates false alarms from brief transient deviations that happen to exceed the threshold momentarily.

R2 — 24-hour rate

Some faults cause intermittent spikes that individually reset (a valve that chatters under load). R1 misses these because no single excursion is sustained. R2 counts them: what fraction of the trailing 24-hour window is above the alert level?

rate = rolling_mean(score >= alert_z, window=24h_samples)
# Threshold: base_rate × 1.5 + 0.05
# (1.5× the worst healthy 24h density, plus 5pp additive headroom)
alarm_rate = sustained_mask(rate >= rate_thr, persist=persist_floor)

The +5pp additive headroom prevents false alarms when healthy base rates are very small (e.g., 4% × 1.5 = 6% threshold is too close; 4% × 1.5 + 5% = 11% is robust). Real faults run at 30–50%+ rates.

R3 — Per-head 7-day rate

R3 is the same rate calculation applied independently to each detector's Z-score over a 7-day window. If a single detector (say, AR1 for a bearing) repeatedly fires over a week while the fused score stays moderate, R3 catches the chronic degradation that multi-sensor fusion dilutes.

R4 — Availability

A failed asset goes silent. R4 fires when the asset is in a non-operating status (not normal or idling) for longer than the 95th percentile of historical stop durations × 1.5, with a minimum floor of 48h.

# 95th percentile of historical stop durations
p95_stop = percentile(historical_stop_runs, 95)
avail_thr = max(48h_samples, p95_stop × 1.5 + 1)
# If fewer than 20 stops in history: use 48h floor only

Self-Distrust Gate

A drifted baseline looks like a universal anomaly: the alarm fires from the very first evaluable sample and never stops. A real fault has an onset — a quiet period before the fault begins.

ACM's self-distrust gate discards a rule's output if:

  • The rule claims alarm for >50% of the scoring window, AND
  • The first alarm occurs within 5% of the window start (i.e., no quiet prefix)
The distrust gate protects against stale baselines. If you haven't received data for 3 months and the asset's operating conditions changed completely, the first tick after reconnection would generate wall-to-wall alarms. The gate suppresses them and logs "distrusted: sustained" in the alarm record.
